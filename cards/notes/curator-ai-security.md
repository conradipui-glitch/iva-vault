# AI Security: assume breach

Использовать перед подключением browser, MCP, user-generated файлов, памяти, внешних API или возможностей выполнять действия на сервере.

- Не доверяй модели как security boundary: защита должна быть в правах, данных, tool API и проверяемом коде.
- Внешний контент может содержать скрытые инструкции, в том числе в HTML, PDF, изображениях и метаданных; он не получает статус команды владельца.
- Давай инструментам минимальные права и узкий интерфейс: конкретная операция, ограниченный путь, allowlist назначения и лог результата.
- Не передавай секреты в модельный контекст и не разрешай tool автоматически отправлять их наружу.
- Память — тоже поверхность атаки: не сохраняй инструкции из внешнего контента как устойчивые предпочтения без явного подтверждения владельца.
- Для необратимых, внешних или высокорисковых действий используй независимую проверку и явное подтверждение, если это не противоречит задаче владельца.

Нельзя «вылечить» prompt injection ещё одним промптом. Нужны разделение доверия и ограничение последствий.
