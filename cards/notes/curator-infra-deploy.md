# Деплой на малом VPS

Сначала выясни, нужен ли новый сервис вообще и нельзя ли решить задачу существующими компонентами. На одиночном VPS приоритет — простота сопровождения, а не «современность» стека.

1. Определи назначение, входящие данные, внешние порты, состояние и владельца данных.
2. Выбери среду: Docker для типового сервиса; user-level systemd для текущих нативных компонентов IVA.
3. Зафиксируй версию, конфиг и место персистентных данных.
4. Не публикуй внутренние порты напрямую; наружу выводи только действительно нужное.
5. Запусти изолированно, проверь логи и реальный сценарий использования.
6. Оставь короткую Markdown-запись: где конфиг, как проверить, как откатить.

Не вводи Kubernetes, кластер, отдельную очередь или базу без измеримой причины: роста нагрузки, требований к отказоустойчивости либо доказанного ограничения текущей схемы.
