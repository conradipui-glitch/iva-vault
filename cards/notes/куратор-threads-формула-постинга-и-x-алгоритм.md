# Куратор Threads: формула постинга и X-алгоритм

Использовать при подготовке и оптимизации постов для Threads (и X). Источники: эмпирический анализ русскоязычных ИИ-аккаунтов Threads (01.08) + открытый X-алгоритм Phoenix (январь 2026).

## Эмпирическая формула Threads (что залетает)
1. Личный опыт с конкретным инструментом (название + время + результат).
2. Хук-опровержение/конфликт первой строкой («НЕ МОЖЕТ? А я…»).
3. Серии из одной темы: 1 тема → 4–7 постов в день разными углами (боль, ошибка, миф, кейс).
4. Конкретика: числа, названия, шаги 1-2-3.
5. Вопрос/открытый вывод в конце — для reply rate.

Ограничение владельца: НЕ постить личный опыт и «цифры-кликбейт» самому — фокус на мысли/вопросы/тренды; личный опыт — только из его слов.

## Сигналы X-алгоритма (Phoenix, янв 2026) — веса
- Reply с ответом автора: **+75** (самый тяжёлый сигнал)
- Like: **+30** (основной сигнал дистрибуции)
- Retweet/репост: **+20**
- Reply без ответа автора: **+13.5**
- Реплаи ≈ **150× лайков** — разговор доминирует над лайками.
- Негатив: not interested / block / mute / report — штрафы, report самый жёсткий.

## Механика для Threads (из алгоритма)
- **Заканчивай пост вопросом** — провоцируй реплаи; отвечай на комменты (ответ автора = +75).
- **Ссылки подавлены**: для Non-Premium ≈ 0% вовлечения → ссылки только в ответ/коммент, не в пост.
- **Треды ≈ 3×** одиночного поста; оптимум ~7 постов (5–10; 8–12 на 47% лучше коротких).
- Первые 30 минут решают охват; частота 3–5 качественных в день с паузами 2–3 ч.
- 3+ хэштегов роняют охват; лучше 1–2 в конце.

## Применение
- Перед публикацией: проверь хук (опровержение/конфликт), конкретику, вопрос в конце, отсутствие ссылок в теле, длину/серийность.
- После: отвечать на комменты (вес +75), не постить ссылки в теле.
