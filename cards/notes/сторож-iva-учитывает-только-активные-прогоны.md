# Сторож Iva учитывает только активные прогоны

22.08.2026 сторож каждые пять минут повторно читал исторические записи usage.jsonl, включая отменённые и завершённые сессии, поэтому присылал повторные тревоги. После исправления он учитывал только прогоны running и предупреждал раз на 40 обращений; причиной исторических сессий были повторные доставки Telegram-моста с устаревшим continuation token и ответом 503.

23.08 сторож дважды поймал реальные длинные ходы (41→84→91 и 44 обращения к модели); владелец потребовал найти причину и исправить («Снова эта история», «Вперёд»). Итог — сторож нового поколения как часть этапа 2 плана оптимизации Iva: data/custom/scripts/iva-watchdog.py под systemd timer 30 секунд, считает реальные usage rows и агрегирует бюджет верхнего хода родителя, включая прямых дочерних субагентов и inline-субагентов.

Пороги: soft 20 — запись события, diagnostic 30, hard 50 — кооперативная отмена только доказанно активного хода через authenticated cancel route. Ответ accepted считается запросом; подтверждение — терминальное событие либо исчезновение точного workflowRun; при неудаче повтор через 90 секунд. Записи Eve run JSON и Telegram inbox напрямую не изменяются; журнал событий content-free, режим 0600. Реальная интеграция отмены подтверждена на disposable-сессии (accepted → turn.cancelled).

Позднее, при закрытии плана оптимизации, таймер сторожа отключён (iva-watchdog.timer disabled, включается одной командой).
