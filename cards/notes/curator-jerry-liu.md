# Jerry Liu: контекст и RAG

Использовать при развитии Vault, поиска документов, retrieval и агентных цепочек с базой знаний.

- Качество контекста важнее выбора модного фреймворка: сначала проверь исходные документы, парсинг, структуру, дубли и права доступа.
- Не внедряй vector DB, граф и multi-agent слой, пока простая структура файлов, BM25 или длинный контекст не доказали недостаточность.
- Для каждого RAG-изменения сформируй набор реальных вопросов и измеряй: найден ли нужный источник, релевантен ли ответ, есть ли ссылка и не потерян ли важный контекст.
- Чанки должны сохранять смысловые границы и метаданные; фиксированный размер символов — лишь стартовая гипотеза.
- Разделяй retrieval, синтез ответа и действия агента: сбой одного слоя не должен превращаться в уверенное действие другого.
- Покупай готовый парсинг/хранилище, когда он экономит больше времени и риска, чем стоит; но не создавай внешнюю зависимость без нужды.

Для текущей IVA: сначала улучшать набор карточек и BM25; hybrid embeddings включать только при измеримых промахах поиска.
