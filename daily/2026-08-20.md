**1. DeepSeek Harness** (170k звёзд за неделю)

170 тысяч звёзд за неделю — столько набрал [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness), открытый агентный фреймворк от DeepSeek AI на TypeScript.

Идея: всё — плагин. Архитектура на Cordis, маркет плагинов уже живёт отдельным репозиторием (1.3k звёзд). Запуск — одна команда: `npx @deepseek-ai/dsh web`, и локальный UI на 3080-м порту готов.

Но нюанс: это developer preview. API ломают между релизами, документация догоняет код. Кто начнёт строить на dsh прямо сейчас — рискует переписывать через месяц.

Ставка понятна: DeepSeek хочет стать не просто моделью, а платформой. Свой маркет, своя экосистема, свой стандарт агентных пайплайнов. Если плагинов станет достаточно, разработчики залипнут — и какая модель под капотом, будет уже не так важно.

Стоит ли прыгать сейчас? Для прода — нет. Чтобы понять, куда движется агентный стек — определённо да. Архитектура «всё есть плагин» пока выглядит чище, чем у конкурентов.

**2. SondeHub** (шутка → война, HN ▲789)

Домен, купленный ради шутки, стал частью военной инфраструктуры.

В 2018-м энтузиаст купил домен для фильтра на трекере метеозондов. Из него вырос [SondeHub](https://sprocketfox.io/xssfox/2026/08/19/sondehub-and-war/) — сервис, где хоббисты по всему миру отслеживали передатчики метеозондов. Пока функция обратных предсказаний — расчёт, откуда запущен зонд — случайно не вскрыла артиллерийские позиции.

В 2021-м военные попросили убрать чувствительные точки. Затем кто-то начал методично долбить API с AWS — забирали прогнозы ветра для наведения дронов и глубоких ударов. Хобби-проект оказался на линии огня.

Разведка Минобороны США запросила данные — автор выставил счёт, не оплатили. NTSB просили информацию о столкновении зонда с самолётом. FAA спрашивали «а что такое метеозонды».

Один энтузиаст собрал то, что не осилили государственные агентства. Это не комплимент — это диагноз.

**3. terminal-code** (VS Code в терминале)

VS Code без VS Code — кто-то наконец сделал это.

[terminal-code](https://github.com/zenbu-labs/terminal-code) от zenbu-labs — полноценная IDE, которая живёт прямо в терминале. Рендерит интерфейс через kitty graphics, ставится одной командой, открывается по `tode .` — и работает по SSH без единого браузера и Electron.

Конфликт хоткеев с терминалом? `--shortcut-setup`. Лень настраивать с нуля? `--import` перетащит конфиги из обычного VSCode.

Почему это не просто игрушка на 548 звёзд: удалённая разработка через SSH до сих пор — боль. VS Code Remote тянет за собой сервер, порт-форварды, иногда ломается на нестандартных хостах. Здесь ничего этого нет — ты уже в терминале, IDE приходит к тебе.

Если вы живёте в tmux и считаете, что IDE — лишнее звено между вами и кодом, попробуйте. Порог входа — один `curl`.

**4. OpenRouter → Stripe** (HN ▲696)

Главный независимый маркетплейс нейросетей [OpenRouter присоединяется к Stripe](https://openrouter.ai/blog/announcements/openrouter-is-joining-stripe/). Сервис прогоняет 10+ триллионов токенов в день, объединяет 400+ моделей и обслуживает 10 миллионов разработчиков.

Главная ставка мультимодельного будущего — нейтральность и устойчивость. Любой независимый маршрутизатор токенов неизбежно упирается в инфраструктурный тупик: сложную микроплатежную систему, борьбу с фродом и абузом. Без финансового гиганта за спиной такой сервис рискует уступить монополистам с бесконечными бюджетами.

Stripe даёт OpenRouter железобетонную финансовую защиту и прямую дистрибуцию на миллионы IT-бизнесов, сохраняя продукт и независимый роадмап. Для разработчиков это отличный знак: монополия одной дефолтной LLM отменяется, а мультимодельность становится базовым стандартом разработки.

**5. SPADE** (self-play RL, arXiv)

Модель сама придумывает себе задачи — и становится умнее. Без единого датасета вручную.

[SPADE](http://arxiv.org/abs/2608.19197v1) — фреймворк, где одна 30B-модель играет две роли одновременно: пишет обучающие среды (исполняемый код с Gym-интерфейсом) и тут же учится в них действовать. Дизайнер среды не даёт лёгких задач и не ставит невозможных — он удерживает агента на грани его текущих возможностей.

Проблема классического RL: среда фиксирована, прогресс упирается в потолок. Здесь потолок движется вместе с агентом.

Результат на 8 бенчмарках: +5.3 в среднем по математике, науке, коду и рассуждениям. Tool-use: +5.7 на BFCL-v4 и +13.9 на ACEBench-Agent.

Почему это меняет расклад: мы привыкли думать, что качество модели ограничено качеством датасета. SPADE показывает, что среда обучения сама может быть обучаемой. Это не очередной трюк с промптами — это шаг к открытому самоулучшению, где модель сама формулирует, чему ей учиться дальше.

**6. ADEPT** (роборуки, arXiv)

Роборука научилась перекладывать предметы в симуляции — и сразу повторила в реальности, без единого примера на физическом железе.

[ADEPT](http://arxiv.org/abs/2608.19182v1) — RL-фреймворк: агент сначала осваивает общий навык «переложить объект» в симе, потом дотачивается под конкретную задачу. Zero-shot перенос проверили на двух платформах — Kuka-Allegro (23 DoF) и Flexiv-Sharpa (29 DoF + тактильные сенсоры). Обе работают от сырых камер и тактильных данных, выполняют длинные манипуляции на человеческой скорости.

Проблема, которую это бьёт: каждую задачу для робота приходилось учить с нуля. ADEPT показывает — базовая «ловкость» переносима. Выучил один раз, адаптируй дёшево.

Если масштабируется, робоманипуляторы перестают быть штучными проектами и становятся платформой.

**7. Orchard** (безопасный локальный ИИ)

Дали агенту API-ключ — он его слил. Классика.

[Orchard](https://github.com/andrew-waters/orchard) решает это архитектурно: macOS-приложение на Swift, которое запускает ИИ-агентов в гипервизорной песочнице. Модель крутится локально на GPU мака через MLX, а контейнер получает к ней доступ без API-ключа — OPENAI_BASE_URL инжектится автоматически через bridge. Ключ не нужен — нечего сливать.

Kill-switch, встроенный чат и терминал, stateful Linux VM — всё из одного окна. Ставится через `brew install orchard`.

Важный сдвиг: безопасность агента перестаёт быть вопросом «доверяй и проверяй». Вместо этого — изоляция на уровне железа. Агент физически не может выйти за границу песочницы и достучаться до секретов хоста. Это не фича, а правильная архитектура.

**8. GC-OPD** (дистилляция длинного контекста)

Qwen3-4B прыгнул с 29 до 40 баллов на длинном контексте — без увеличения размера.

Проблема дистилляции: учитель подсказывает потокенно, но на длинных текстах его подсказки расходятся с итоговой оценкой задачи. Модель учится «правильным» шагам, которые ведут к неправильному ответу.

[GC-OPD](http://arxiv.org/abs/2608.19181v1) решает это элегантно: нормализует оценки учителя и верификатора внутри группы роллаутов, считает «остаток разногласия» и раздаёт его по токенам. Учитель больше не врёт — его сигнал откалиброван под финальный результат.

Qwen3-8B тоже подрос: 44.65 против 43.56 у vanilla OPD. Маленькие модели начинают держать длинный контекст не хуже больших — и дело не в архитектуре, а в качестве обучающего сигнала.

[Код](https://github.com/SolereZhang/GC-OPD) открыт.
